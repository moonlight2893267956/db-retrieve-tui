# dbr 使用手册

## Summary

dbr 是一个在终端里交互式查询 MySQL 分库分表的命令行工具（Python 2.7 实现）。它自动识别分库分表结构、把「选库 → 选表 → 填条件」拆成逐步向导，支持跨分表聚合与全局排序，并提供表格直显、分页、排序和导出。它还支持按「值清单文件」批量查询（自动分批生成 `IN (...)`，无需手写上千个值）。本手册用 `paybase` 数据源的示例数据，给出可直接照做的交互案例与精确期望结果。

## 一、安装与启动

**导读**：装一次即可在整台机器上用 `dbr` 命令；数据源默认复用你终端里已有的 mysql alias，无需任何配置。

### 安装

```bash
cd ~/db-retrieval-cli-py
./install.sh
```

`install.sh` 会探测 Python 2.7、在 `~/bin/dbr` 建立软链、并保证 `~/bin` 在 `PATH` 里（不在则幂等地追加到 shell 启动文件）。装完后新开终端即可直接用：

```bash
dbr --help
```

### 启动

```bash
dbr                 # 交互模式：默认使用当前 shell 的 mysql alias 作为数据源
dbr --no-clear      # 关闭「步骤切换清屏」，保留全部滚动历史
dbr --config=/path/to/conf.py   # 附加配置（见案例 4：智能缩表）
```

数据源直接取当前登录 shell 的 alias，**名字即数据源名**，密码沿用 alias 里已有的。启动后第一步就是选择数据源：

```text
  dbr  MySQL 分库分表查询
  ────────────────────────────────────────────────────────────────────────
  选择数据源
  1  cifdb   10.0.0.10:3307  cif_user
  2  miscdb   10.0.0.10:3308  misc_ro
  3  paybase   10.0.0.10:3306  db_user
  4  statdb   10.0.0.10:3308  misc_rw
  5  vipcifdb   10.0.0.10:3307  cif_rw
  0 返回   q 退出
  选择 (1-5/5):
```

## 二、一次查询的四个步骤

**导读**：dbr 把一次查询固定成四步，每步一屏。本手册后续案例都按这个流程走，看懂这一节，后面案例只需看关键差异。

| 步骤 | 界面标题 | 你做什么 |
|------|----------|----------|
| ① 选数据源 | `选择数据源` | 输入序号，如 `3` 选 `paybase` |
| ② 选库 | `选库` | 输入序号选「逻辑库组」，可再输索引缩到具体库 |
| ③ 选表 | `选表` | 输入序号选「逻辑表组」，可再输索引缩到具体表 |
| ④ 填条件 → 预览 → 执行 | `条件` / `预览` / `结果` | 分步填字段 / where / LIMIT /（可选）高级子句，回车执行 |

**选库**：列表里给的是「逻辑库组」（如 `demo_db_{db}` 代表 100 个分库）。选中一个库组后，它会**行内追问**一个索引：回车 = 遍历整组全部库；输入索引（如 `78`）= 只查 `demo_db_78`。

**选表**：同理，`t_order_log_{db}_{table}` 代表每库 10 张分表。选中后回车 = 遍历全部 10 张；输入索引（如 `4`）= 只查 `..._78_4`。

**填条件**：分四次输入，各自回车用默认值。

```text
  SELECT 字段 [*]:                       ← 回车用默认 *；也可填字段/聚合表达式
  where 条件（回车=不加）:                ← 回车不加 where
  LIMIT 行数（NONE=不限制） [100]:        ← 回车用默认 100；NONE 不限制
  › 高级子句（回车=跳过；o 排序 / g 分组 / h HAVING）:  ← 回车跳过
```

**查表结构（`?`）**：不确定字段名或字段含义时，在 `SELECT 字段` 或 `where 条件` 提示处输入 `?`，就地列出所选表的字段结构（字段名 / 类型 / 可空 / 键 / 默认值 / 注释），看完**自动回到原提示**继续输入，不用另开窗口：

```text
 表结构  demo_db_78  ·  10 张表
 ────────────────────────────────────────────────────────────────────────
 10 张表结构一致，取自 demo_db_78.t_order_log_78_0
  字段             │ 类型                │ 可空 │ 键   │ 默认 │ 注释
  ──────────────────┼─────────────────────┼──────┼──────┼──────┼──────────────
  F_id             │ bigint(20)          │ 否   │ 主键 │ -    │ 自增字段
  F_user_id        │ bigint(20) unsigned │ 否   │ 索引 │ -    │ uid
  F_credit_amount  │ bigint(20)          │ 否   │ -    │ 0    │ 授信金额(分)
  F_status         │ tinyint(3) unsigned │ 否   │ -    │ 0    │ 1为开通；2为关闭
 提示：可复制字段名用于 SELECT 字段 / where 条件
```

选的是**表组**（如 `t_order_log_{db}_{table}` 展开 10 张分表）时，结构一致则只展示一次并注明「10 张表结构一致」；不一致则逐表分段展示。结构用 `information_schema` 一条 SQL 取齐，不可用时自动回退 `SHOW FULL COLUMNS`，结果一致。

> 终端较窄时，结构表会**自动把宽度让给更重要的列**：整列全空的列（如该表没有注释时的「注释」）不再展示；
> 列宽不足时优先保证「字段名 / 类型 / 注释」完整，`默认` 等次要列最后才被截断（不会压成只剩一个 `…`）。

**预览即执行**：填完条件后展示将要执行的 SQL，**回车执行**、`n` 取消。若 where 命中路由字段，会自动缩表并在预览里标注。

**导读**：以下案例全部在 `paybase`（`10.0.0.10:3306`）上用示例数据跑通，每条都给出**照做的按键顺序**与**精确期望结果**。数据源统一按 `3`（paybase）选择。

案例用到的固定测试数据（库 `demo_db_78`）：

| 表 | 说明 | 行数 |
|----|------|------|
| `t_order_log_78_0..9` | 免密代扣流水（10 张分表） | 合计 258 |
| `t_order_sign_78_4` | 免密签约 | 22 |
| `t_user_setting_78_*` | 用户支付方式设置 | — |

### 案例 1：单表精确查询

**场景**：已知分库分表后缀，直接查某一张分表并按状态过滤。

**按键顺序**（每行一次回车）：`3` → `3` → `78` → `1` → `t_order_log_78_4` → 字段 → where → 回车 → 回车 → 回车(执行) → `q`

逐步说明：

1. `3` 选数据源 `paybase`
2. `3` 选库组 `demo_db_{db}`
3. `78` 缩到具体库 `demo_db_78`
4. `1` 手动输入表名
5. `t_order_log_78_4` 输入完整表名（避免选组时歧义，直接精确命中 1 张表）
6. 字段填 `F_id,F_user_id,F_credit_amount,F_status,F_channel,F_modify_time`
7. where 填 `F_status=1`

预览与结果：

```text
  目标   1 张表  ·  单表

  SELECT F_id,F_user_id,F_credit_amount,F_status,F_channel,F_modify_time FROM demo_db_78.t_order_log_78_4 WHERE F_status=1 LIMIT 100

  › 回车执行 · n 取消:
  ✓ 执行完成  ·  成功 1  ·  耗时 0.02s

  查询结果  26 行 × 6 列
  ────────────────────────────────────────────────────────────────────────
  来源  t_order_log_78_4
   F_id │ F_user_id  │ F_credit_amount │ F_status │ F_channel │ F_modify_time
  ──────┼────────────┼─────────────────┼──────────┼───────────┼─────────────────────
   1    │ 2000000001 │ 5000            │ 1        │ channel_a     │ 2024-09-29 08:19:59
   3    │ 2000000002 │ 50000           │ 1        │ channel_a     │ 2024-11-25 08:41:05
   4    │ 2000000003 │ 5000            │ 1        │ channel_a     │ 2024-11-27 16:51:58
   ...
```

**期望结果**：26 行（`t_order_log_78_4` 中 `F_status=1` 的记录数，与 `SELECT COUNT(*) ... WHERE F_status=1` 一致）。

> 终端较窄或列太多时，dbr 会自动切换**竖排详情视图**（逐行 `字段 值` 卡片），保证长值不被截断。上例 6 列时是横排表格；`SELECT *`（14 列）时会自动竖排。

### 案例 2：跨分表遍历

**场景**：不指定分表后缀，一次查遍同库下某组全部分表。

**按键顺序**：`3` → `3` → `78` → `3` → 回车 → 回车 → 回车 → 回车 → 回车(执行) → `q`

逐步说明：

1. `3` 选 `paybase`
2. `3` 选库组，`78` 缩到 `demo_db_78`
3. `3` 选表组 `t_order_log_{db}_{table}`
4. **回车**（不缩表）= 遍历该库全部 10 张分表
5. 条件全用默认（`*` / 无 where / LIMIT 100）

预览：

```text
  目标   10 张表  ·  占位符遍历

  SELECT * FROM
      demo_db_78.t_order_log_78_0 LIMIT 100
      demo_db_78.t_order_log_78_1 LIMIT 100
      demo_db_78.t_order_log_78_2 LIMIT 100
        … 其余 7 张

  › 回车执行 · n 取消:
  ✓ 执行完成  ·  成功 10  ·  耗时 0.25s

  查询结果  258 行 × 15 列
```

**期望结果**：10 张表全部成功，合计 **258 行**（与 10 张表 `COUNT(*)` 求和一致）。多来源结果会自动增加一个 `table` 列标明每行的来源表；单一来源时则隐藏来源列，只在顶部用一行注明来源。

> 提示：`LIMIT` 在多表遍历时是**每张表**的上限（非全局），预览区会标注。

#### 跨库遍历与展开速度

若在「选库」时**不缩到具体库**（直接回车），`{db}` 会匹配该数据源下**全部**同前缀的库，
此时选表屏会提示将遍历多少个库：

```text
  库模板 demo_db_{db} 将遍历 100 个库（表清单取自 demo_db_00）

  paybase  ·  demo_db_00  ·  选表
```

> 注意：选表屏标题里的 `demo_db_00` 只是**用于读取表清单的样本库**，
> 不代表只查这一个库——实际会遍历上面提示的 N 个库。
> 只想查一个库时，请在「选库」那步输入库索引（如 `78`）缩到具体库。

展开表的表清单用 `information_schema` **一条 SQL 取齐**（而非逐库 `SHOW TABLES`），
100 个库的展开从约 3~9 秒降到 1 秒以内。若 `information_schema` 不可用，会自动回退为逐库读取，结果不变。

### 案例 3：跨分表分组聚合（全局合并）

**场景**：统计整个分表组的分布，例如「按状态统计流水条数」。

**按键顺序**：`3` → `3` → `78` → `3` → 回车 → 字段 `F_status, COUNT(*) AS c` → 回车(无 where) → `NONE` → `g` → `F_status` → `o` → `c DESC` → 回车(结束高级) → 回车(执行) → `q`

关键步骤说明：

1. 前 4 步同案例 2，选定 `demo_db_78` 的全部 10 张 log 表
2. **字段**填 `F_status, COUNT(*) AS c`
3. **LIMIT** 填 `NONE`（聚合查询不限制行数）
4. 在高级子句提示行输入 `g`，编辑 `GROUP BY` 为 `F_status`
5. 再输入 `o`，编辑 `ORDER BY` 为 `c DESC`（降序）
6. 回车结束高级子句编辑

预览与结果：

```text
  目标   10 张表  ·  占位符遍历
  ✓ 将跨 10 张表按分组键合并为全局聚合（COUNT/SUM 相加、MAX/MIN 取极值、AVG 加权）；LIMIT 为每表上限，非全局。

  SELECT F_status, COUNT(*) AS c FROM
      demo_db_78.t_order_log_78_0 GROUP BY F_status ORDER BY c DESC
      demo_db_78.t_order_log_78_1 GROUP BY F_status ORDER BY c DESC
        … 其余 8 张

  › 回车执行 · n 取消:
  ✓ 执行完成  ·  成功 10  ·  耗时 0.21s

  聚合结果  2 行 × 2 列
  ────────────────────────────────────────────────────────────────────────
   F_status │ c
  ──────────┼─────
   1        │ 217
   2        │ 41
```

**期望结果**：全局合并后 2 行 —— `F_status=1` 共 **217** 条、`F_status=2` 共 **41** 条（合计 258，与案例 2 一致）。`ORDER BY c DESC` 在合并后**全局排序**（217 > 41）。

> 多表聚合的组合规则：`COUNT/SUM` 相加、`MAX/MIN` 取极值、`AVG` 按 `SUM/COUNT` 加权；`ORDER BY` 与 `HAVING` 都在跨表合并后统一判定。`GROUP_CONCAT`、`COUNT(DISTINCT ...)`、`STDDEV` 等无法跨表合并，多表时会被明确拒绝并提示缩到单表。

### 案例 4：智能缩表

**场景**：where 里给出路由字段的值，dbr 据此算出唯一目标库表，避免全库全表遍历。

**前提**：为数据源配置分库分表规则。新建 `rule.conf`（Python dict，UTF-8）：

```python
CONFIG = {
    "shardingRules": {
        "paybase_user_setting": {
            "shardingType": "numeric",
            "dbPrefix": "demo_db_",
            "tablePrefix": "t_user_setting_",
            "routingField": "F_user_id",
            "routingMethod": "substring",
            "routingParams": {"dbIndexStart": -3, "dbIndexLength": 2, "tableIndexStart": -1},
        }
    }
}
```

该规则含义：`F_user_id` 末 3 位中，前 2 位是库索引、末 1 位是表索引。

**启动**：`dbr --config=./rule.conf`

**按键顺序**：`3` → `3` → `00` → `2` → 回车 → 字段 `F_id,F_user_id,F_pay_method` → where `F_user_id=1000000003` → 回车 → 回车(执行) → `q`

关键步骤：选库组后输 `00` 缩到 `demo_db_00`；选表组 `2`（`t_user_setting_{db}_{table}`）后**回车遍历 10 张**；where 填 `F_user_id=1000000003`。

预览与结果：

```text
  目标   1 张表  ·  单表

  SELECT F_id,F_user_id,F_pay_method FROM demo_db_00.t_user_setting_00_3 WHERE F_user_id=1000000003 LIMIT 100

  › 回车执行 · n 取消:
  ✓ 执行完成  ·  成功 1  ·  耗时 0.02s

  查询结果  1 行 × 3 列
  ────────────────────────────────────────────────────────────────────────
  来源  t_user_setting_00_3
   F_id │ F_user_id  │ F_pay_method
  ──────┼────────────┼──────────────────────────────────────────
   1    │ 1000000003 │ BALANCE,agreement_50@U000EXAMPLE_TOKEN…
```

**期望结果**：`1000000003` 末 3 位 `003` → 库索引 `00`、表索引 `3`，命中 `demo_db_00.t_user_setting_00_3`，**1 行**。候补流程「选 10 张表」被自动缩成 1 张（预览里「目标 1 张表 · 单表」）。

> 未配置 `routingField` 规则时，带 where 的字段不会触发缩表，将按所选范围遍历；此时可在选表步骤直接用**具体表索引**缩小范围。

### 案例 5：聚合函数 SUM / AVG

**场景**：对单表求合计/均值，或对分表组求全局合计。

**单表聚合**（查 `t_order_log_78_4` 的条数、合计、均值）：

**按键顺序**：`3` → `3` → `78` → `1` → `t_order_log_78_4` → 字段 `COUNT(*) AS n, SUM(F_credit_amount) AS total, AVG(F_credit_amount) AS avg` → 回车 → `NONE` → 回车 → 回车(执行) → `q`

```text
  查询结果  1 行 × 3 列
  ────────────────────────────────────────────────────────────────────────
  来源  t_order_log_78_4
   n  │ total  │ avg
  ────┼────────┼───────────
   31 │ 265000 │ 8548.3871
```

**期望结果**：`n=31`、`total=265000`、`avg=8548.3871`（与 `COUNT/SUM/AVG` 直查一致）。

**跨表聚合**（同一字段，但选整组 10 张表）：前 4 步改为选中 10 张 log 表，其余同上。此时未加 `GROUP BY`，dbr 会提示：

```text
  ✓ 提示：多表聚合但未分组，将按表逐行列出（共 10 行）；需要全局合计请加 GROUP BY 分组键

  查询结果  10 行 × 4 列
  ────────────────────────────────────────────────────────────────────────
   n  │ total  │ avg        │ table
  ────┼────────┼────────────┼────────────────────────
   18 │ 165000 │ 9166.6667  │ t_order_log_78_0
   35 │ 300000 │ 8571.4286  │ t_order_log_78_1
   31 │ 470000 │ 15161.2903 │ t_order_log_78_2
   ...
```

**期望结果**：每张分表一行，各自给出该表的 `n/total/avg`。**无 `GROUP BY` 时多表聚合不做全局合计**（各表结果语义独立）；需要全局一个总数时，加 `GROUP BY` 分组键（见案例 3）或缩到单表。

> 内部用于跨表 `AVG` 加权的辅助列（`SUM/COUNT`）不会出现在结果里，导出也不含。

### 案例 6：导出结果

**场景**：把结果落盘为文件（支持 txt / csv / markdown / html）。

**操作**：在任意查询的**结果页**输入 `e`，选格式序号，回车用默认路径（或输入自定义路径）。

以案例 1 的结果为例（导出 csv）：

```text
  › q 返回 · s 排序 · e 导出 · v 行详情  回车 q: e

  导出格式
  1  text  (.txt)
  2  csv   (.csv)
  3  markdown  (.md)
  4  html  (.html)
  选择 (1-4/4): 2
  导出路径 [<root>/output/result_YYYYMMDD_HHMMSS.csv]:
  ✓ 已导出 22 行 → <root>/output/result_YYYYMMDD_HHMMSS.csv
```

**期望结果**：文件为 UTF-8，列顺序与展示一致，并**额外包含来源列** `db_index,table_index,table_name`（导出保留完整来源信息，便于溯源）。案例 1 导出 22 行：

```csv
F_id,F_user_id,F_credit_amount,F_status,db_index,table_index,table_name
1,2000000001,5000,2,78,4,t_order_sign_78_4
2,2000000002,50000,1,78,4,t_order_sign_78_4
...
```

> 单次导出有行数上限（默认 1000）；超出会中断并提示已写入的行数。

### 案例 7：非交互一次性查询 `--query`

**场景**：熟练用户或脚本里直接给一条查询，无需进入交互。

**语法**：`dbr --db=<数据源> --query='<库>.<表> [字段 | where | LIMIT | order by … | group by … | having …]'`

**示例 A —— 单表 + where**：

```bash
dbr --db=paybase --query='demo_db_78.t_order_log_78_4 F_id,F_user_id,F_credit_amount,F_status | F_user_id=2000000003'
```

```text
  查询结果  3 行
  ────────────────────────────────────────────────────────────────────────
  来源  t_order_log_78_4
   F_id │ F_user_id  │ F_credit_amount │ F_status
  ──────┼────────────┼─────────────────┼──────────
   4    │ 2000000003 │ 5000            │ 1
   5    │ 2000000003 │ 0               │ 2
   6    │ 2000000003 │ 20000           │ 1
```

**期望结果**：3 行（`F_user_id=2000000003` 的流水）。

**示例 B —— 跨分表分组聚合**：

```bash
dbr --db=paybase --query='demo_db_78.t_order_log_{db}_{table} F_status, COUNT(*) AS c | | NONE | group by F_status | order by c DESC'
```

```text
  聚合结果  2 行
  ────────────────────────────────────────────────────────────────────────
   F_status │ c
  ──────────┼─────
   1        │ 217
   2        │ 41
```

**期望结果**：`{db}` / `{table}` 占位符按实际库表展开，跨 10 张表合并为全局聚合，结果与案例 3 一致。

> 占位符 `{db}` / `{table}` 的展开范围 = 实际 `SHOW DATABASES` / `SHOW TABLES` 的真实集合；`order by … / group by … / having …` 段可任意顺序、可缺省。

### 案例 8：批量值清单查询（IN 分批）

**场景**：手上有一份值清单（如一批 `log_id`、`F_user_id`），要按这些值在分表里批量捞记录。手写 `IN (...)` 不现实——dbr 会读值文件、自动分批生成 `IN (...)`，逐表逐批查询后汇总，并给出「命中 / 未命中」统计。

> 这类需求过去常靠临时脚本实现（CSV 读值 → 分批 `IN` → 汇总写文件）。现在直接由 dbr 内建完成，无需单独脚本、无需额外放密码文件。

#### 值清单文件目录

把清单文件（`.csv` / `.txt` / `.tsv` / `.list` / `.dat`）放进**基准目录**（默认 `<dbr>/data/`），
进入批量模式时会**自动扫描并列成菜单**，选一个即可，无需输入完整路径：

```text
  值清单文件
  基准目录  /home/user/db-retrieval-cli-py/data
  1  手动输入路径
  2  user_ids.csv
  3  status_ids.csv
  0 返回   q 退出
  选择 (1-4/4): 2
  ✓ 已选择  user_ids.csv
```

- 菜单里始终有「手动输入路径」；也可直接写文件名（dbr 会到基准目录查找）。
- 用 `--data-dir=<目录>` 可指定其它基准目录；目录不存在时 dbr 会自动创建。
- 目录为空时会提示「暂无可用文件」并引导手动输入。

#### 交互方式

在「查询方式」提示处输入 `i`，从文件菜单里选一个清单：

```text
  › 查询方式（回车=普通；i=值清单批量 IN）: i
  ✓ 已选择  user_ids.csv
  字段名（如 F_log_id）: F_user_id
  ✓ 已加载 2 个去重值（原始 3 行）（已识别表头并跳过首行） · 取列「F_user_id」
  接下来设置 SELECT 字段 / LIMIT / 排序等；where 由值清单自动生成
```

随后与普通查询一样填 `SELECT 字段` / `LIMIT` / 高级子句；**where 不用填**，由值清单自动生成。预览区会给出压缩后的 WHERE 与查询次数：

```text
  ✓ 值清单批量查询  ·  2 个值  ·  1 批（每批 ≤1000）
  将对每张表执行以下 WHERE（分批）：
      F_user_id IN ('1000000003','1000000005')  /* 共 2 个值，1 批，每批 ≤1000 */
  共将执行 10 次查询（表 10 × 批 1）

  › 回车执行 · n 取消: 
```

执行后结果头部汇总统计：

```text
  ✓ 批量执行完成  ·  成功 10  ·  耗时 0.21s

  查询结果  2 行 × 3 列
  ────────────────────────────────────────────────────────────────────────
  输入 2 值  ·  命中 2  ·  未命中 0  ·  结果 2 行
```

> 预览里的 WHERE 只展示首尾各若干值 + 批次说明，**不会把上千个值铺满终端**。

#### 非交互方式

`--file` 可写**纯文件名**（到基准目录 `<dbr>/data/` 查找），也可写完整路径：

```bash
dbr --db=paybase \
    --query='demo_db_00.t_user_setting_{db}_{table} F_user_id' \
    --field=F_user_id \
    --file=user_ids.csv
```

```text
[信息] 批量值清单：2 个值 · 1 批（每批 ≤1000）· 目标 10 张表 · 共 10 次查询
[信息] 批量完成：成功 10 · 失败 0 · 耗时 0.21s

  批量结果  2 行
  ────────────────────────────────────────────────────────────────────────
  输入 2 值  ·  命中 2  ·  未命中 0  ·  结果 2 行
```

**期望结果**：`1000000003` → `t_user_setting_00_3`，`1000000005` → `t_user_setting_00_5`。

#### 分批与多表

值数量超过批大小时自动分批。例：2499 个值按默认批 1000 → 3 批：

```bash
dbr --db=paybase --query='demo_db_78.t_order_sign_78_4 F_status' \
    --field=F_status --file=big_ids.csv --batch-size=1000
# [信息] 批量值清单：2499 个值 · 3 批（每批 ≤1000）· 目标 1 张表 · 共 3 次查询
```

选表时若选的是**表组模板**（如 `t_order_sign_{db}_{table}`），则对「每张表 × 每个批次」分别查询后汇总：

```bash
dbr --db=paybase --query='demo_db_78.t_order_log_78_{table} F_status' \
    --field=F_status --file=status_ids.csv
# [信息] 批量值清单：2 个值 · 1 批（每批 ≤1000）· 目标 10 张表 · 共 10 次查询
```

#### 参数说明

| 参数 | 含义 | 默认 |
|------|------|------|
| `--field=<字段名>` | 用于 `IN` 的字段（必填，须为合法标识符） | — |
| `--file=<值文件>` | 值文件；纯文件名到基准目录查找，含 `/` 则相对 dbr 根目录 | — |
| `--data-dir=<目录>` | 值清单基准目录（相对路径相对 dbr 根目录） | `<dbr>/data/` |
| `--batch-size=<N>` | 每批 `IN` 的值个数（1–5000，越界回落 1000） | 1000 |
| `--has-header` | 强制首行是表头（丢弃） | 自动识别 |
| `--no-header` | 强制无表头（首行也是值） | 自动识别 |
| `--column=<N>` | 多列文件取第 N 列（0 基）；**不指定时**按字段名在表头中自动定位 | 自动定位 |

#### 多列文件与自动定位列

CSV 导出（如表数据导出的 `result_*.csv`）往往是**多列 + 带表头**。此时不必去数第几列：

- **不指定 `--column`**：dbr 会在表头里查找与 `--field` 同名的列（大小写不敏感）并自动取该列。例：`--field=F_user_id` 会自动定位到表头里的 `F_user_id` 列。
- **指定 `--column=<N>`**：显式指定优先，按列号取（用于表头无同名列、或想取别的列时）。
- **表头里找不到 `--field` 同名** 且未指定 `--column`：报错并列出该文件可用列，避免静默取错列。

交互模式会在加载成功后提示实际取用的列：`✓ 已加载 20 个去重值（原始 21 行）（已识别表头并跳过首行） · 取列「F_user_id」`。

> 示例（用导出文件回查，无需数第几列）：
> ```bash
> dbr --db=paybase \
>     --query='demo_db_78.t_user_setting_{db}_{table} F_user_id' \
>     --field=F_user_id --file=output/result_20260913_151825.csv
> # 自动定位 F_user_id 列 → 20 个值 · 10 张表 → 命中 20 / 未命中 0 / 结果 20 行
> ```

#### 注意事项

- **值文件格式**：每行一个值；空行计入「跳过空行」；重复值自动去重并保持首次出现顺序。
- **多列文件**：默认按 `--field` 在表头中自动定位列；也可用 `--column` 显式指定取第几列（显式指定优先）。
- **表头自动识别**：首行「像字段名」（合法标识符且非纯数字）且第二行不像时，判为表头并跳过。混合列名/值的文件建议显式用 `--has-header` / `--no-header` 指定，避免误判。
- **命中统计口径**：命中/未命中按**字段值**计（一个值命中多行只算一次命中）；结果行数是所有命中的总行数。若 SELECT 未包含该字段，dbr 会**自动并入**该列以保证统计可行。
- **结果不去重**：批次之间按汇总拼接（与逐批查询的语义一致）；如需去重请导出后自行处理。
- **字段名合法性**：`--field` 必须是合法标识符（字母/数字/下划线，不以数字开头），否则拒绝执行，防止 SQL 注入。
- **查询次数**：总次数 = 表数 × 批数；超过 500 次时交互预览会给出耗时提醒。

#### 数据闭环验证

以下用例在 `paybase` 上用**示例 CSV 数据**验证通过（值文件均为示例导出/历史测试文件）：

| 用例 | 输入 | 结果 |
|------|------|------|
| 历史测试清单 | `sample_ids.csv`（表头 + 2 行 `F_user_id`） | 跨 10 张分表命中 2，定位到 `t_user_setting_00_3` / `_00_5` |
| 导出回查闭环 | `result_20260913_151825.csv`（示例导出 20 行），自动定位 `F_user_id` | 20 值 → 10 表，命中 20 / 未命中 0 / 结果 20 行（与源导出自洽） |
| 显式指定列 | 同上但加 `--column=0` | 取 `F_id` 列 → 命中 0（证明 column 优先） |
| 字段不存在 | `--field=ZZZ` | 报错 `Unknown column 'ZZZ'`，计入失败批 |

> 「导出回查闭环」是最强的一致性验证：把 dbr 导出的 CSV 取列后回查同一批数据，命中数与源导出逐行对得上。

## 五、常见问题

**导读**：启动、连接、显示相关的常见问题及处理。

**Q：提示「未找到可用的 mysql 客户端」**
安装 mysql/mariadb 客户端并确保 `/bin/mysql` 可执行、在 PATH 中。

**Q：提示「未在当前 shell 中找到 mysql alias 数据源」**
当前 shell 没有可解析的 `mysql` alias。在 `~/.bash_profile` 加一行
`alias paybase='mysql -hHOST -PPORT -uUSER -pPASSWORD'` 后重开终端；或用 `--config` 指定数据源。

**Q：中文显示乱码**
工具默认以 `--default-character-set=utf8` 连接并做 GBK 兜底转码；请确认终端为 UTF-8。

**Q：SQL 预览里表名被 `…` 截断**
说明当前终端可用宽度不足。dbr 会优先保留表名的尾部区分位；把终端调宽即可完整显示。若确实放不下，会保留完整的「库.表」而只截断子句。

**Q：多表聚合为什么不是一行总数**
未加 `GROUP BY` 时，多表聚合的结果按表逐行列出（各表语义独立），dbr 会给出提示。要全局一个总数，请加 `GROUP BY` 分组键，或直接缩到单表。

**Q：提示「聚合函数 XXX 无法跨分表合并」**
`GROUP_CONCAT`、`COUNT(DISTINCT ...)`、`STDDEV` 等无法跨表合并。请缩到单表查询（选具体库/表索引，或配置 `routingField` 规则自动缩表）。
